# Трапезная МДА — конструктор отчёта и генератор Excel: дизайн

Дата: 2026-10-12. Статус: на согласовании.

## 1. Цель

Дать оператору собрать структуру отчёта из наших залов — группы с подытогами и
отдельные строки общих итогов — и на её основе выдавать Excel двух видов:
«за день» и «за N дней». Формат берётся из приложенного образца
(`docs/otherFile/Система_учета_питающихся (1)(2).xlsx`, листы «Отчет 1д» и
«Отчет 10д»).

## 2. Термины

- **Группа** — именованный набор залов с порядком; может показывать подытог.
- **Общий итог** — именованная строка, которая считается по выбранным залам или
  по всем активным залам.
- **Резерв** — приём, отмеченный администратором после дедлайна; входит в общий
  счёт, но выводится отдельной колонкой.

## 3. Границы

Входит: хранение шаблона, страница-конструктор для оператора, переработка Excel
для дневного и многодневного отчёта, колонки резерва под галочкой.

Не входит: изменение экранных таблиц отчёта (они остаются как есть), лист
«Зал.месяц» из образца, назначение групп по каталогу LDAP.

## 4. Модель данных

Четыре плоские таблицы; дубли исключены уникальными индексами, а не логикой UI.

```
report_group          id, name, sort_order, show_subtotal
report_group_hall     group_id → report_group, hall_id → halls, sort_order
                      UNIQUE (group_id, hall_id)

report_total          id, name, sort_order, all_halls
report_total_hall     total_id → report_total, hall_id → halls, sort_order
                      UNIQUE (total_id, hall_id)
```

- Один зал может входить в несколько групп — это разрешено (см. §7).
- `all_halls = true` — состав считается во время отчёта по всем активным залам,
  включая добавленные позже; строки `report_total_hall` в этом случае не нужны.
- Никаких связей «итог → группа»: итог всегда считается по залам.
- `on delete cascade` для дочерних строк; удаление зала (если появится)
  вычищает связи.

## 5. Панель-конструктор

Страница оператора «Конструктор отчёта» (`/operator/report-template`), два блока.

**Группы.** Добавить группу → название, галочка «Показывать подытог», список
залов (добавить/убрать, порядок стрелками). Зал, уже добавленный в эту группу, в
её списке недоступен; в другую группу — доступен.

**Общие итоги.** Добавить итог → название, переключатель «Все залы» либо выбор
конкретных залов с порядком.

Залы — все активные залы БД. Правка только у оператора; бухгалтер конструктор не
видит.

Сохранение — целиком (`PUT` всего шаблона): конфигурация маленькая, а полная
замена исключает гонки частичных правок и «полупустые» состояния.

## 6. Лист «Отчет 1д»

- Заголовок: «Количество питающихся по залам за:» + дата в формате `дд.мм.гггг`.
- Шапка: `Завтрак | Обед | Полдник | Ужин`; под каждым приёмом —
  `Итог | <тип> … | Рез.` (`Рез.` только при включённой галочке резерва).
  Колонки типов — по всем активным типам питания в их порядке; в шапке
  выводится название типа из БД как есть (оператор может назвать тип коротко,
  как «Мяс» в образце).
- Строки:
  1. для каждой группы по порядку — её залы (подпись = название зала из БД,
     без колонки «№ п/п»), затем строка «Итого <группа>», если включён подытог;
  2. затем строки общих итогов в заданном порядке.
- «Итог» по приёму включает резерв; «Рез.» — из них резерв.

## 7. Лист «Отчет Nд»

- Заголовок: период `с дд.мм.гггг по дд.мм.гггг`, `N` = число дней.
- Колонки: на каждую дату — блок из 4 приёмов, при включённом резерве — из 8
  (`Звтр, Звтр рез., Обд, Обд рез., Плдн, Плдн рез., Ужн, Ужн рез.`). Над блоком
  объединённая шапка: день недели + дата.
- Строки:
  1. для каждой группы: строка с именем группы (сумма по всем типам) и под ней
     строка на каждый активный тип питания. Строка группы выводится всегда —
     она же служит подписью блока; галочка «подытог» на неё не влияет;
  2. строки общих итогов.
- Отдельных строк залов в этом листе нет — как в образце.

## 8. Резерв

- Галочка «Показывать резерв» на странице отчёта рядом с кнопкой Excel; выбор
  запоминается в браузере и передаётся параметром `reserve=true`.
- В дневном листе — колонка `Рез.` в каждом приёме.
- В многодневном — парная колонка к каждому приёму (блок из 8 колонок).
- В резервных колонках выводятся только резервные отметки; обычные колонки
  включают и обычные, и резервные (как сейчас в отчётах).

## 9. Семантика сумм

- Подытог группы = её залы, каждый один раз.
- Строка общего итога = выбранные залы (или все), **каждый зал один раз**, даже
  если он входит в несколько групп.
- Следствие: при пересечении групп «ИТОГО» меньше суммы подытогов. В шапке
  отчёта — сноска об этом.
- Если зал входит в две группы, он отображается в обеих, а в общий итог
  попадает однажды.
- Зал, не включённый ни в одну группу, в дневном листе не выводится, но
  учитывается в итогах «все залы». Чтобы он появился, его надо добавить в
  группу.

## 10. API

- `GET  /api/v1/operator/report-template` — шаблон целиком.
- `PUT  /api/v1/operator/report-template` — замена целиком (группы + итоги).
  Валидация: непустые названия, залы существуют и активны, нет дублей зала
  внутри группы/итога, `all_halls` и список залов взаимоисключающи.
- Экспорт (`/accountant/report/export`, `.../period/export`) получает параметр
  `reserve: bool = false` и строит файл по шаблону.

## 11. Пустой шаблон и совместимость

Если в шаблоне нет ни групп, ни итогов — экспорт работает по-старому: плоский
список залов и общий итог. Приложение остаётся работоспособным до настройки
конструктора.

## 12. Тестирование

Модель и API:
- дубль зала внутри группы отклоняется;
- дубль зала внутри итога отклоняется;
- `all_halls` вместе со списком залов — ошибка валидации;
- удаление группы/итога чистит дочерние строки.

Генератор:
- дневной лист: залы по группам, подытог только при галочке, строки итогов в
  заданном порядке;
- зал в двух группах: в подытогах обеих, в общем итоге — один раз;
- `all_halls` учитывает зал, добавленный после настройки шаблона;
- колонка `Рез.` появляется только при `reserve=true`;
- многодневный лист: блок из 4/8 колонок на дату, строки групп и типов;
- пустой шаблон — прежний плоский отчёт;
- числа совпадают с экранным отчётом за те же даты.

## 13. Выкат

1. Миграция создаёт четыре таблицы; существующие данные не затрагиваются.
2. Оператор настраивает группы и итоги.
3. Бухгалтер выгружает Excel как раньше; при пустом шаблоне формат прежний.
4. Откат: удалить настройки (пустой шаблон) — отчёт вернётся к плоскому виду.

## 14. Производительность

Многодневный отчёт считает состояние по каждому питающемуся на каждую дату (как
сейчас). При росте числа людей и дней это станет заметно; в плане
предусмотреть возможность перейти на один агрегирующий запрос, если замеры
покажут проблему. Формат отчёта от этого не зависит.
